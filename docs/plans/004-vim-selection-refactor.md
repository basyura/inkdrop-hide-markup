# Vim の選択処理の再設計

## 目的

コミット `ac9dbbb` と `36f65c1` で追加・変更された処理を見直し、位置補正の判断と状態更新の関係を読み取れる構造にする。既存の操作仕様は維持する。

## 現状の問題

- 表示上のカーソル位置、Vim 内部の位置、記号を含めた選択範囲の扱いが混在している。
- モードや操作対象の判定が重複し、共有状態を更新する順序を追う必要がある。
- 選択範囲の計算、削除・変更操作への対応、DOM のカーソル表示補正が密結合している。
- 関数分割後も条件式や三項演算子が複雑で、処理を適用する理由が分かりにくい。

## 修正方針

1. `docs/specs/001-hide-markup.md` と実際の Vim ライブラリの処理順序を確認し、現在必要な補正とその理由を整理する。
2. Vim の文字単位の選択と通常の選択の入口を明確にし、繰り返す対象判定と座標変換を共通化する。
3. カーソル移動先、本文全体を覆う場合の記号を含めた範囲、選択方向の計算を、副作用のない処理として分離する。複雑な条件式は名前付きの判断と早期リターンで表す。
4. Vim 内部位置の同期、削除・変更後の位置補正、描画の補正を計算処理から分離する。共有する状態とその有効期間を明示し、不要な状態や補正があれば取り除く。
5. DOM 補正や非同期の再同期は、実際のライブラリの挙動を調べて必要性を判断する。必要な場合は理由を記録し、専用の処理に閉じ込める。
6. ファイル分割は責務に沿って行い、単なる関数の移動で終わらせない。他のプラグインが補正した移動先を保持する。

## 検証

- 既存の 51 件のテストを維持する。
- 再構成した処理の境界条件について、実際の Vim ライブラリを使う回帰テストを追加する。前後方向、選択の拡大・縮小、入れ子・隣接構文、部分選択と全体選択、削除・変更、対象外モードなどから既存テストで不足するケースを選ぶ。
- `npm test` を実行する。
- 実装と追加テストを関連仕様と照合し、既存仕様を意図せず変更していないことを確認する。
- DOM の模擬環境で確認できない描画上の制約は、完了報告に記載する。

- 記号を含む選択の拡張は、構文範囲が入れ子または互いに独立している性質を利用し、内側から一度ずつ処理する方式に変更した。
- `lib/vim-selection.js` の `VimSelection` に移動予約と Vim 内部位置の同期を集約。文字単位の Visual モード判定と座標変換を共通化した。
- `lib/visual-cursor.js` に DOM 補正と復元・破棄処理を分離した。
- Vim ライブラリの実装を確認した結果、選択範囲からカーソルを描画するための DOM 補正と、`c` が削除後に古い論理位置へ移動する際の補正は維持した。他の更新リスナーが位置を戻した場合の非同期再同期も、対象位置が一致する場合に限定して維持した。
- 回帰テストを 5 件追加。両端が入れ子の構文の拡大・縮小、隣接構文の回数指定とコピー、別行での変更と入力、一時表示中の選択、行・矩形選択への非適用を検証した。
- `npm test` は既存 51 件と追加 5 件の計 56 件が成功した。
- 関連仕様の通常・Vim 移動、挿入切り替え、Visual 選択と編集、一時表示、対象外の操作と照合し、操作仕様を変更していないことを確認した。
- Inkdrop 実機の描画は未確認。DOM の自動テストは従来どおり模擬環境での検証となる。

## 追加修正：Visual カーソルの復元位置

- `み**込む数**の` を文字単位 Visual で選択して戻る際の位置を確認する。
- 内部位置と選択範囲は自動テスト環境で正常だった一方、描画補正の復元処理は Vim が再描画した新しい横位置も古い値に戻していた。
- 復元対象が自分の補正した表示のままかを判定し、Vim による再描画済みの位置を上書きしないようにする。
- 実際の Vim 操作にカーソル DOM の再描画を組み合わせた回帰テストを追加し、強調・削除構文で右端まで選択して戻る各位置を確認する。
- 関連仕様の選択拡大・縮小と表示文字上のカーソル維持に従い、`npm test` を実行する。

### カーソル復元の修正結果

- 回帰テストは修正前に、Vim が再描画した `80px` が保存済みの `70px` に上書きされて失敗した。
- 保存した補正後の文字と横位置がともに現在の表示と一致する場合だけ復元するように変更した。Vim の新しい描画は保持する。
- 強調・削除の両方で `み` から `の` まで選択して `h` で戻る全移動について、内部位置とカーソルの文字・横位置を検証した。
- `npm test` は計 63 件成功。選択を縮めても論理位置を維持し、表示文字上にカーソルを重ねる既存仕様と整合することを確認した。
- Inkdrop 実機では未検証のため、ユーザーが報告した描画症状の解消は実機での確認が必要。模擬環境では内部位置の不正移動は再現せず、上記の描画位置の上書きを再現・修正した。

## 追加修正：非表示記号上のカーソル描画を分離

- 期待動作は `の` から `h` 一回で `数` に直接戻ること。先の復元処理の修正だけでは実際の症状の検証が不十分だった。
- 実機で選択範囲が縮んでも、ブロックカーソルが右側に残る表示を確認した。Vim は記号を含めた選択範囲の端点からカーソルを描画するため、非表示記号の位置と論理位置が異なる。
- Vim が所有するカーソルの座標・文字の上書きをやめる。補正が必要な場合だけ専用のレイヤーにカーソルを描画し、元のカーソルを一時的に隠す。
- 座標は Vim の DOM の現位置から差分計算せず、論理位置の文字座標から決定する。測定と描画には CodeMirror の `requestMeasure` を使う。
- 遅れて Vim 本体がカーソルを再描画しても、表示カーソルが非表示記号上へ移動しないことを回帰テストで検証する。補正不要時・終了時・破棄時には元の表示に戻す。

### 専用カーソルへの変更結果

- 座標・文字を元のカーソルへ上書きする実装を廃止し、補正中は専用カーソルを表示する実装に置き換えた。
- `の` から `h` で `数` に戻った後に Vim 本体の描画を遅れて適用しても、表示カーソルの位置・文字が変わらないことを既存の回帰テストに追加した。
- スクロール量を含む座標、元カーソルの再生成への追従、破棄時の表示復元についてテストを 1 件追加した。
- `npm test` は計 64 件成功。表示文字上へのカーソル配置、選択方向と縮小、通常のカーソル表示への復帰について既存仕様との整合性を確認した。
- 修正前の症状は実機で確認した。修正後の実機再確認は未完了。アプリの再読み込みによる変更反映後に確認する必要がある。
